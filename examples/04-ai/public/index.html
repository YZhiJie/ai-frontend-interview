04 · AI 应用开发示例

本目录所有接口均为 零 npm 依赖、纯 node:http 的 MOCK 实现， 不需要任何 API Key，node server.mjs 即可运行。 MOCK 的意义是让前端把流式渲染、中断、异步任务轮询、失败重试这套交互机制跑通； 模型能力本身在真实项目中通过后端代理接入。

真实项目中的对应替换点（Mock → 生产）

  • 固定回答 → 真实大模型：服务端把请求转发到 OpenAI 兼容接口，地址通过环境变量配置，如 LLM_BASE_URL=https://api.example.com/v1、LLM_API_KEY=sk-xxx；模型返回的 SSE 字节透传给前端即可，协议格式（data: ...\n\n、[DONE]）基本一致。
  • API Key 绝不下发浏览器：前端永远只请求自己的后端 / Serverless / Edge Function，由后端代理承担鉴权、限流、审计与内容安全；Key 写在浏览器代码或打包产物里等于公开，会被盗刷。
  • 内存 Map → 持久化任务表：文生图任务状态在生产环境应放 Redis / 数据库，服务重启不丢；进度获取也可换成 SSE 推送。
  • base64 dataUrl → CDN URL：小图临时预览可用 base64；正式成图应上传对象存储返回签名 URL，载荷小、可缓存、可懒加载。
  • EventSource 的取舍：本 demo 用 fetch 手写解析，是因为真实 LLM 网关普遍要求 POST + 自定义鉴权头（Bearer token），而原生 EventSource 不支持；纯 GET 订阅通知类场景则优先 EventSource，自带自动重连与 Last-Event-ID。
