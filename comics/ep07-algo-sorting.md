# EP.07 排序复杂度之旅

> 对应正文：[docs/07-algorithms.md](../docs/07-algorithms.md)（覆盖 ALGO-B1 大 O 记号 / ALGO-B2 冒泡排序 / ALGO-I1 手写快速排序 / ALGO-I4 排序稳定性与 TimSort）· 配套示例：`../examples/07-algorithms/i1-quick-sort.ts`、`../examples/07-algorithms/run-all.ts`、`../examples/07-algorithms/i2-heap-topk.ts`

## 剧情回顾

- **第 1 格**：小研十万条数据用冒泡排序，页面直接卡死。码叔一眼定罪：O(n²) 正在替你烧 CPU——n = 100000 时比较次数约 100 亿次。
- **第 2 格**：码叔用柱状图摆出两个数量级的差距：冒泡约 100 亿次比较，O(n log n) 的快排只要约 170 万次，十分钟级与毫秒级之别。
- **第 3 格**：小研演示快排"分家术"：以首位 5 为基准，一次 partition 把 `[5 1 8 3 9 2]` 甩成 `[1 3 2] 5 [8 9]`，左右两段再各自递归。
- **第 4 格**：结案两个高频坑：快排最坏会退化 O(n²)（已有序 + 固定首位基准）；V8 的 `Array.sort` 用的是 TimSort，不是快排。

## 知识点拆解

### 第 1 格 · O(n²) 如何卡死页面

- 大 O 描述的是耗时随输入规模 n 增长的**趋势上界**，n 足够大时常数项与低阶项都可忽略；
- 冒泡排序相邻比较、大数右浮，每轮把最大值"冒泡"到末尾，平均/最坏时间 O(n²)、空间 O(1)，因相邻交换而是稳定排序；
- 十万条数据比较次数达百亿量级，主线程长时间被占满，页面自然失去响应；
- 加 `swapped` flag 后，原本有序的输入一轮无交换即可退出，最好情况优化到 O(n)，但随机/逆序输入仍是 O(n²)。

### 第 2 格 · 两个数量级的差距

- 常见复杂度从慢到快：O(1) < O(log n) < O(n) < O(n log n) < O(n²)；
- 同一份十万条数据：冒泡 n² 量级 ≈ 100 亿次比较；快排 n log₂n ≈ 100000 × 17 ≈ 170 万次，相差约 6000 倍；
- 体感上就是分钟级与毫秒级——量级差一档，体感差一生；
- 空间复杂度也要记账：原地排序 O(1)，归并排序需 O(n) 辅助数组，递归还要计入调用栈深度。

### 第 3 格 · 快排分家术

核心是 partition：选基准、扫一遍、小的甩左大的甩右、基准归位，然后左右递归：

```js
function partition(arr, left, right) {
  // 随机选基准并换到左端，防止有序输入退化 O(n²)
  const r = left + Math.floor(Math.random() * (right - left + 1));
  [arr[left], arr[r]] = [arr[r], arr[left]];

  const pivot = arr[left];
  let i = left + 1; // i：下一个"小于基准"元素的存放边界
  for (let j = left + 1; j <= right; j++) {
    if (arr[j] < pivot) {
      [arr[i], arr[j]] = [arr[j], arr[i]];
      i++;
    }
  }
  [arr[left], arr[i - 1]] = [arr[i - 1], arr[left]]; // 基准归位
  return i - 1;
}
// 图示：[5 1 8 3 9 2] → [1 3 2] 5 [8 9]，两段各自递归到不可再分
```

- 不变量：partition 结束时基准左侧全部小于它、右侧全部不小于它，两侧天然可分治；
- 每次大致对半则递归深度 O(log n)、每层总扫描 O(n)，合计 O(n log n)；
- 完整实现可直接跑 `../examples/07-algorithms/i1-quick-sort.ts`，全章节算法由 `run-all.ts` 统一执行。

### 第 4 格 · 快排不是免死金牌

- 最坏情况：每次基准恰好是最值（完全有序数组 + 固定取首位），一侧只剩 n-1 个元素，递归 n 层退化成 O(n²)，栈深也变 O(n)；
- 随机基准让"输入分布"与"基准选择"解耦，期望回到 O(n log n)，三数取中、小区间转插入、三路快排是同类工程手段；
- V8 的 `Array.prototype.sort` 采用 **TimSort**（归并 + 插入混合）：最坏 O(n log n)、天然稳定，对局部有序的真实数据可趋近 O(n)，也避免了被构造出 O(n²) 攻击；
- 码叔结论：先看数据规模与有序度再选算法，小数据不必炫技。

## 坑点清单

1. **快排最坏 O(n²)**：已有序/近有序输入叠加固定基准会导致分区极度失衡；用随机化基准或三数取中规避，大量重复键再上三路快排；
2. **以为内置 sort 是快排**：V8 用 TimSort，归并 + 插入混合且是稳定排序；且 `sort()` 默认按 Unicode 码位比较，数字必须传比较器 `(a, b) => a - b`；
3. **小数据盲目炫技**：几十上百条数据直接用内置 sort 即可，常数差异在小规模下毫无体感，手写排序只在理解原理与特殊约束时值得。

## 自测 3 题（含答案）

1. 十万条数据用冒泡和快排，比较次数差多少？——**冒泡约 100 亿次（O(n²)），快排约 170 万次（O(n log n)），相差约 6000 倍，对应分钟级与毫秒级**。
2. 快排为什么会退化到 O(n²)？怎么防？——**每次基准都是最值、分区极度失衡（如有序数组固定取首位）；随机基准或三数取中把输入与选点解耦即可**。
3. V8 的 Array.sort 为什么用 TimSort？——**它是归并+插入的混合稳定排序，最坏 O(n log n)、局部有序数据趋近 O(n)，既满足 ES2019 的稳定性要求，又避开了快排最坏情况的攻击面**。
