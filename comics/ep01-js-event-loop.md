# EP.01 JS 事件循环

> 对应正文：[docs/01-javascript.md](../docs/01-javascript.md)（JS-B4 Promise 执行顺序 / JS-I1 宏任务与微任务混合调度 / JS-I2 async/await 混合顺序 / JS-A1 浏览器与 Node 事件循环差异）· 配套示例：`../examples/01-javascript/i1-macro-micro-order.ts`、`../examples/01-javascript/i2-async-await-order.ts`、`../examples/01-javascript/b4-promise-order.ts`

## 剧情回顾

- **第 1 格**：小研困惑 `setTimeout(fn, 0)` 为什么不是立即执行；码叔让她先看两支队伍——定时器只保证「尽早入队」。
- **第 2 格**：码叔画出一轮循环的四步：调用栈 → 微任务队列 → 宏任务队列 → 渲染，栈一清空队列才有得跑。
- **第 3 格**：小研抛出 `setTimeout` 撞上 `Promise` 的混合输出题，实证「3 一定排在 2 前面」。
- **第 4 格**：码叔结案两个高频坑，并给出八字节奏：微任务不清完，宏任务不上场。

## 知识点拆解

### 第 1 格 · 0 毫秒的误会

- `setTimeout(fn, 0)` 不是「零延迟立即执行」，而是一张进入宏任务队列的「加急票」；
- 它的执行要先等两件事完成：**同步调用栈清空** + **微任务队列清空**；
- 即使 delay 为 0，也要等下一轮循环才能取出，无法抢占微任务（与 JS-B4 答案一致）。

### 第 2 格 · 一轮循环四步走

- ① 同步代码在调用栈中立即执行；
- ② 栈清空后，**清空整个微任务队列**：`Promise.then`、`queueMicrotask`、`await` 的后续代码都在其中；
- ③ 取出**一个**宏任务执行：`setTimeout` / `setInterval`；
- ④ 浏览器在宏任务间隙进入渲染判断，`requestAnimationFrame` 回调在绘制前执行，然后回到 ①，周而复始；
- 关键机制：宏任务执行期间新产生的微任务，会在**该宏任务结束后立即**被清空，而不是等所有宏任务跑完（JS-I1）。

### 第 3 格 · 混合输出题

```js
console.log('1');
setTimeout(() => console.log('2'));
Promise.resolve().then(() => console.log('3'));
console.log('4');
// 同步 → 微任务全清 → 宏任务
// 输出：1 4 3 2
```

- 同步阶段依次打印 `1`、`4`，期间 setTimeout 回调进入宏任务队列、then 回调进入微任务队列；
- 同步结束先清空微任务，打印 `3`；最后才取宏任务打印 `2`；
- 更复杂的 8 行混合题（`1 8 4 7 5 2 3 6`）见 `i1-macro-micro-order.ts`，可直接 `npx tsx` 跑断言。

### 第 4 格 · await 的真面目

- `await` 下一行代码不会当场执行，而是作为续体进入微任务队列，等价于 `.then` 的回调；
- async 函数在 `await` 之前的部分仍是同步执行，Promise 构造函数的 executor 也是同步的（JS-I2）；
- Node ≥ 11 已改为「每个宏任务后立即清空微任务」，与浏览器趋同；`process.nextTick` 有独立队列且优先级高于 Promise 微任务（JS-A1）。

## 坑点清单

1. **await 之后的代码 ≈ then 微任务**：把 `await` 后面的语句当同步代码读，是输出顺序题翻车的头号原因；
2. **每个宏任务跑完都要清空全部微任务**：宏任务开跑前，微任务队列必须为空——在 setTimeout 回调里新注册的微任务，会插队到下一个 setTimeout 之前；
3. 跨端代码（SSR / CLI）不要依赖微任务与宏任务的精确穿插顺序，应用 await / 队列原语显式表达时序，别拿 `setTimeout(0)` 做时序兜底。

## 自测 3 题（含答案）

1. `setTimeout(fn, 0)` 是零延迟立即执行吗？——**不是，它只是尽早进入宏任务队列，要等同步栈和微任务都清空后的下一轮循环才执行**。
2. 第 3 格代码为什么输出 `1 4 3 2` 而不是 `1 4 2 3`？——**同步先打印 1、4；栈清空后先清空全部微任务打印 3，再取宏任务打印 2，微任务优先于宏任务**。
3. `await foo()` 后面的代码什么时候执行？——**foo 同步部分先执行，后续代码被包装成微任务续体（等价于 .then 回调），在同步代码结束后按微任务队列顺序执行**。
